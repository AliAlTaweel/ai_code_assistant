# AgileOps Multi-Agent MCP — Local Implementation Plan

Build a multi-agent AI system where specialized agents coordinate via an Orchestrator and interact with local data through a Model Context Protocol (MCP) server.

---

## Architecture Overview

- **Orchestrator Pattern:** An Orchestrator Agent routes requests and manages handoffs between a **Resourcing Specialist Agent** and a **Financial Risk Agent**.
- **Local LLM:** Ollama running `qwen2.5-coder` or `llama3` locally at `http://localhost:11434/v1`.
- **Tool Protocol:** Local TypeScript/Go MCP Server exposing tools for querying consultants, projects, margins, and audit logs.
- **Local DB:** PostgreSQL 16 + `pgvector` running via Docker Compose.
- **Frontend UI:** React + Tailwind CSS featuring a Multi-Agent Handoff Visualizer, Live MCP Trace Log, and Human-in-the-Loop approval queue.

## PHASE 1: Docker Compose, Schema & Seed Data

### Objective
Initialize local PostgreSQL with pgvector, seed operational records, and configure Ollama endpoints.

### Prompt Phase 1
Act as a Senior Systems Architect. Create a local environment for an enterprise multi-agent platform:
1. `docker-compose.yml` with `pgvector/pgvector:pg16` on port 5432.
2. `schema.sql` containing tables for `users`, `consultants` (with skill embeddings), `projects`, `assignments`, and `agent_audit_logs`.
3. `seed.sql` populated with 10 consultants and 5 project opportunities.
4. Shell script `scripts/setup_local_env.sh` to initialize the database and check Ollama status at `http://localhost:11434`.

## PHASE 2: Local MCP Tool Server (RBAC & Tool Definitions)

### Objective
Create a central MCP server that all agents use to fetch operational context and execute actions.

### Prompt Phase 2
Act as a Principal Engineer. Build a Model Context Protocol (MCP) server in TypeScript/Go (`@modelcontextprotocol/sdk`):
1. Expose MCP Tools:
   - `search_consultants_by_skill`: Search profiles by skill tags and availability.
   - `calculate_project_margin`: Calculate margins based on cost/bill rates (Requires `FINANCE_READ` role).
   - `create_pending_assignment`: Create a draft project assignment requiring approval.
2. Enforce RBAC: If an agent calls `calculate_project_margin` without `FINANCE_READ` context, return a structured `PERMISSION_DENIED` error.
3. Add a unit test suite verifying schema validation and RBAC enforcement.

---

## PHASE 3: Multi-Agent Handoff & Orchestration Loop

### Objective
Build the multi-agent coordination system with explicit agent handoffs and tool execution logic.

### Prompt Phase 3
Act as an AI Multi-Agent Architect. Build the multi-agent orchestration runtime (`agent/orchestrator.ts`):
1. Implement 3 explicit agents:
   - **Orchestrator Agent:** Receives user query, plans execution steps, and routes tasks.
   - **Resourcing Agent:** Calls `search_consultants_by_skill` via MCP to find candidate matches.
   - **Finance Agent:** Calls `calculate_project_margin` via MCP to check profitability.
2. Agent Handoff Mechanism: Implement structured handoffs (e.g., Orchestrator -> Resourcing Agent -> Finance Agent -> Orchestrator).
3. Human-In-The-Loop (HITL) Gate: When the Finance Agent calls `create_pending_assignment`, freeze state execution and emit a `PENDING_APPROVAL` status.
4. Add simulation scripts testing multi-agent handoffs for both authorized and restricted user roles.

## PHASE 4: Local Offline Evaluation Suite

### Objective
Build a multi-agent benchmark script measuring routing accuracy, MCP tool execution precision, and hallucination prevention.

### Prompt Phase 4
Act as an AI Quality Engineer. Build an evaluation framework (`evals/runner.ts`):
1. Define test cases covering multi-agent task delegation, permission boundaries, and ambiguous constraints.
2. Evaluate:

   - `MCP Tool Precision`: Were the correct tools executed with valid parameters?

3. Output test results in `eval_report.json` and CLI format.
